## 확인한 결과

- `npm run build`: TypeScript strict 검사와 Vite 배포 빌드 통과.
- `npm test`: 9개 통과, 실패·스킵 0. 엔진 불변식, 자동 진행·다음 라운드, 타이머·중복·포화 검사를 포함합니다.
- `npm run test:browser`: 실제 Chromium에서 자동 플레이, Mock 사과 효과, 콤보 5회 접수, 새로고침 복구, 기프트 게임 오버 후 다음 라운드, 브라우저 오프라인 중 게임 진행, WebSocket 재연결, 다른 Origin의 변경 요청 403, 100개 기프트 접수, 페이지 JS 오류 0 확인.
- `npm run test:restart`: 빌드 서버를 실제 종료한 동안 게임 시간이 계속 진행됨을 확인. 같은 JSON 저장소로 재시작한 후 epoch·총 이벤트 수가 유지되고 WebSocket 재접속 및 정적 게임 화면 제공이 정상 동작. 페이지 JS 오류 0.
- 기존 `/workspace/world-flag-marble-race-3d`의 Git 변경 사항 없음.
- `npm ci --cache /workspace/.npm-cache --no-audit --no-fund` 재설치 후 빌드·핵심 테스트 재통과. 의존성 선언과 lockfile로 재현 가능성을 확인했습니다.
- 실제 배포 서버 브라우저 soak: **60,814ms**, Mock 기프트 활성, 페이지 오류 0, 10초 간격 샘플에서 점수 40→100→160→230→280→350으로 진행. 이것은 30분 또는 24시간 검증이 아닙니다.
- 최종 배포 서버에서 브라우저 전체 검사를 재통과했고, 손상된 속도 값을 앱 초기화 전에 주입했을 때 새 라운드로 복구되는 검사도 통과했습니다. 종료 직전 저장이 테스트 주입을 덮어쓰는 경우를 피하도록 초기화 시점에 주입했습니다.

설치 스크립트와 시작 지침을 클라우드 환경 설정 초안의 `install_script`, `start_skill`에 저장했습니다. 초안 저장은 현재 환경 변경의 게시나 새 작업에서의 복원 검증을 의미하지 않습니다. 환경 설정에서 검토·저장 후 게시가 필요합니다. 최초 검증 당시에는 로컬 Git 저장소만 준비했습니다. 이후 사용자 요청으로 https://github.com/hyusmedia/hyuz-auto-snake-live 의 main 브랜치에 소스를 업로드했습니다.

## 발견·수정한 문제

- 초기 CSS의 불필요한 import로 빌드 실패: 제거 후 빌드 통과.
- 백그라운드 탭의 requestAnimationFrame 중단으로 게임 재시작 지연: 시뮬레이션 타이머와 렌더링을 분리하고 브라우저 검사를 통과. 브라우저의 백그라운드 타이머 감속 자체는 남아 있으므로 전경 실행·OBS 설정이 필요합니다.
- 화면 높이가 뷰포트를 초과: 전체 레이아웃의 크기를 측정해 맞추도록 변경. 최종 스크롤 영역 1080×1920 확인.
- 자동 브라우저 검사의 버튼 선택자가 DEMO 접근성 텍스트와 불일치: 실제 접근성 이름에 맞춰 검사 수정.
- 환경 샌드박스가 npm 연결, tsx IPC, esbuild 설치 검증, 로컬 서버 바인딩을 차단: 허용된 실행 권한으로 실행하여 해결. TLS·패키지 검증은 유지했습니다.

## 재현 방법과 한계

README의 개발/빌드 실행 절차를 사용합니다. `npm run test:restart`는 3001 포트를 직접 사용하므로 실행 중인 서버를 먼저 종료하세요. `npm run test:browser`와 `npm run test:soak`는 별도 실행 서버가 필요합니다. 빌드 서버를 검사하려면 `TEST_BASE_URL`을 `http://127.0.0.1:3001`로 설정합니다.

스크린샷과 soak 결과는 실행 시 `test-results/`에 생성됩니다. 가속 시뮬레이션은 실제 브라우저 수 시간 실행, 메모리 누수 부재, Windows 호환성 또는 OBS 송출 안정성을 증명하지 않습니다. 실제 API 인증·유료 테스트·방송 송출은 수행하지 않았습니다. GitHub 소스 업로드와 실제 방송 검증은 별개입니다.

## 참고 이미지형 화면 업데이트

사용자 참고 이미지에 맞춰 검은 1080×1920 화면, 금색 LEVEL, 8개 DEMO 안내 카드, 보라색 정사각형 게임판, 점무늬 초록 뱀과 큰 점수 표시를 적용했습니다. 상단 인물·왼쪽 위 선물 알림·하단 오른쪽 마지막 선물 제공자 영역은 기본 `/overlay`에서 자식 요소 없이 비워 둡니다. 원본 방송의 인물·닉네임·선물 이미지는 포함하지 않았습니다.

업데이트 후 빌드와 Chromium 기능 검사를 통과했습니다. 빈 영역 세 곳, 정사각형 게임판, 1080×1920 레이아웃을 확인했으며 자동 플레이·기프트·콤보·재연결·새로고침·손상 저장소 복구 검사도 통과했습니다. 게임 엔진 규칙과 시작 길이는 유지했으므로 뱀은 사과를 먹으면서 길어집니다.

## 큰 눈·사과, 미로형 이동, 회전·섭취 음향 업데이트

눈은 5.5×7에서 8×10, 사과는 9×8에서 14×12 캔버스 반경으로 확대했습니다. AI는 안전 공간을 우선한 뒤 2~5칸 안팎의 가변 직진·회전, 최근 32칸 방문 회피를 섞고, 80회 이동 동안 사과를 못 먹으면 BFS 추적을 우선합니다. 회전 간격과 방문 이력을 스냅샷에 보존하고 이전 저장소 형식도 읽습니다.

회전마다 노이즈·밴드패스 기반 키보드 클릭, 사과 섭취마다 850→170Hz의 짧은 팝음을 생성합니다. 오디오 노드는 종료 시 연결을 해제하고 동시 음향 수를 제한합니다. `/overlay`의 ENABLE SOUND 버튼으로 브라우저 오디오 권한을 활성화할 수 있습니다.

검증: TypeScript/Vite 빌드, 핵심 테스트 10개(30분·1시간 가속 검사와 400회 이동의 굴곡·사과 진행 검사 포함), 전체 브라우저 회귀 검사 통과. 실제 Chromium Web Audio 검사에서 회전 클릭 10회·사과 팝 1회·비영 출력 파형(peak 약 0.474)·running 상태·관리자 음소거를 확인했으며 페이지 오류는 0개입니다. 주파수 예약 후 즉시 AudioParam.value를 읽는 첫 검사 방식은 Chromium의 오디오 처리 시점과 맞지 않아, 예약된 시작 주파수와 실제 출력 파형을 함께 확인하도록 수정했습니다. Windows 스피커·OBS 음향 실기기 청취 및 장시간 운영은 별도 검증이 필요합니다.
